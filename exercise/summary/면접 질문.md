# 면접 질문

### JDK, JRE, JVM은 각각 무엇이며 어떤 관계인가요?
- JDK: Java Development Kit, 자바 프로그램을 개발하기 위한 도구, 실행 환경 뿐 아니라 javac 같은 컴파일러와 개발 도구를 포함
- JRE: Java Runtime Environment, 자바 프로그램을 실행하기 위한 환경, JVM과 Java 프로그램 실행에 필요한 표준 라이브러리 등을 포함
- JVM: Java Virtual Machine, 자바 바이트코드를 실제로 실행하는 가상 머신, .class 파일의 바이트코드를 읽어서 현재 운영체제와 CPU에서 실행할 수 있도록 함

### Java 소스코드를 작성한 뒤 실행되기까지의 과정을 설명해주세요. .java와 .class는 어떻게 다른가요?
- 자바 소스코드는 개발자가 .java 파일로 작성함
- 이 소스파일을 컴파일러가 컴파일하면 .class 파일이 생성됨
- 클래스 파일에는 JVM이 이해할 수 있는 바이트코드가 들어 있음
- 프로그램을 실행할 때 JVM이 이 바이트코드를 해석하여 실행함

### Java 프로그램이 서로 다른 운영체제에서 실행될 수 있는 이유는 무엇인가요?
- 각 운영체제에 맞는 JVM이 바이트코드를 실행하기 때문임
- 소스코드를 컴파일한 클래스 파일은 같아도 그것을 해석하는 JVM이 운영체제마다 다르기 때문임
- 따라서 JVM 자체는 운영체제에 종속적임(Windows는 Windows용 JVM, Linux는 Lunux용 JVM, mac은 mac용 JVM이 따로 있음)

### IntelliJ의 Run 버튼을 누르면 어떤 작업이 이루어질까요? 프로젝트에 JDK를 설정하는 이유는 무엇인가요?
- Run 버튼을 누르면 소스 코드를 컴파일하고 생성된 바이트코드를 JVM에서 실행함
- 프로젝트에 JDK를 설정하는 이유는 어떤 Java 컴파일러, 표준 라이브러리, Java 버전을 사용할 것인지 지정하기 위함

### Git과 GitHub는 어떻게 다른가요? 소스코드의 변경 이력을 관리하면 어떤 점이 좋을까요?
- Git은 버전 관리 시스템으로 변경 이력을 관리할 수 있음
- GitHub는 Git 저장소를 원격으로 저장하고 공유할 수 있도록 제공하는 서비스임
- 변경 이력을 관리하면 언제 어떤 코드가 변경되었는지 확인할 수 있고, 기능을 수정한 뒤 문제가 발생하였을 때 어떤 변경이 문제를 만들었는지 확인하기 쉽고 되돌릴 수도 있음

### AI의 도움을 받아 작성한 코드를 사용하기 전에 무엇을 확인하나요? 직접 확인했던 사례를 설명해주세요.
- AI가 작성한 코드가 내가 요구한 사항에 부합하는지 확인
- 코드가 실제로 컴파일되고 정상적으로 실행되는지 확인
- 코드가 예상대로 동작하며 예외 입력에서도 제대로 동작하는지 확인

### 코드가 예상대로 동작하지 않을 때, AI에게 어떤 정보를 제공하면 도움이 될까요?
- 내가 어떤 동작을 기대하고 예상했는지
- 실제로 어떤 결과가 나왔는지

- 어떤 조건에서 예상하지 못한 동작이 발생하였는지
- 내가 예상하는 잘못된 부분 또는 이미 실행해 본 해결 방법
- 실행 환경, 라이브러리의 버전

### 컴파일 단계의 오류, 실행 중 발생하는 오류, 실행은 되지만 결과가 잘못된 경우는 어떻게 다른가요?
- 컴파일 단계의 오류: 소스코드를 컴파일할 수 없는 경우, 컴파일되지 않았으므로 빌드하여 프로그램이 만들어질 수 없음, 대개 언어 문법적으로 문제가 있는 경우
- 실행 중 발생하는 오류: 프로그램을 실행하는 도중에 문제가 발생하는 경우, 코드 상에 문제는 없고 정상적으로 컴파일되지만 프로그램 동작 중에 문제가 발생함, 예를 들어 숫자를 입력받도록 프로그램을 만들었지 문자를 입력한 경우 예외 발생할 수 있음
- 실행은 되지만 결과가 잘못된 경우: 컴파일도 되고 오류도 발생하지 않지만 실행 결과가 의도와 다른 경우
- 컴파일 오류 -> 컴파일러가 알려주는 위치와 메시지를 확인
- 런타임 오류 -> 예외와 Stack trace 확인
- 논리 오류 -> 실행 흐름, 조건, 중간 값 등을 디버거와 테스트로 확인

### 기본 타입과 참조 타입은 어떻게 다른가요? 다른 변수에 대입할 때 각각 무엇이 복사되나요?
- 기본 타입: 변수 자체에 값을 복사하고 다른 변수에 대입하면 그 값이 복사됨, byte, short, int, long, float, double, char, boolean 타입이 있음
- 참조 타입: 변수에 객체를 가리키는 참조값(주소)를 저장하고 다른 변수에 대입할 때 참조값이 복사됨, 따라서 두 참조 변수가 같은 객체를 가리키게 됨

### 동일성과 동등성은 어떻게 다른가요? 문자열을 비교할 때 ==와 equals()의 결과가 달라질 수 있는 이유는 무엇인가요?
- 동일성은 두 참조가 같은 객체를 가리키는가를 의미 (==으로 확인)
- 동등성은 두 객체를 논리적으로 같은 값이라고 볼 수 있는가를 의미 (equals()로 확인)
- 다음과 같이 문자열을 비교할 때 s1과 s2는 서로 다른 String 객체를 가리키므로 ==의 결과는 false이지만 두 객체의 문자열 내용은 같으므로 equals()는 true가 됨

```Java
String s1 = new String("abc");
String s2 = new String("abc");

System.out.println(s1 == s2); // false
System.out.println(s1.equals(s2)) // true
```

### null과 빈 문자열 ""은 어떻게 다른가요? NullPointerException이 발생하는 간단한 예를 들어주세요.
- null은 아무 객체도 참조하고 있지 않음을 나타냄
- 빈 문자열("")은 길이가 0인 실제 String 객체임
- NullPointerException이 나타나는 예(null 인 참조에서 메서드나 필드에 접근하면 발생할 수 있음)

```Java
String a = null
System.out.println(a.length()); // NullPointerException
```

### double a = 7 / 2;와 double b = (double) 7 / 2;의 결과는 왜 다른가요?
- 전자: 7과 2는 int형으로 7 / 2를 하면 int 연산으로 결과가 몫인 3이 나오고 이걸 double 형 변수 a에 대입하면서 3.0이 됨
- 후자: (double) 7 로 7을 먼저 double 형으로 변환(7.0)하므로 실수 나눗셈이 수행되어 결과가 3.5가 되고 이를 double형 변수 b에 대입하게 됨

### 정수 오버플로란 무엇인가요? 주문 금액이나 누적 합계를 계산할 때 어떤 점을 확인해야 하나요?
- 정수형은 표현할 수 있는 범위가 있음
- 예를 들어, byte는 -128부터 127까지의 정수를 표현할 수 있어서 표현 가능한 최댓값을 넘어가면 잘못된 값이 만들어지는 오버플로가 발생함, 값이 127인 byte형 변수에 1을 더하면 11111111 -> 00000000
- 주문 금액이나 누적 금액에서는 덧셈이나 곱셈 결과가 범위를 넘어갈 수 있기 때문에 가능한 최댓값이 타입 범위를 넘어가는지 확인하고 중간 계산 시 오버플로가 일어날 수 있는 상황을 고려해야 함, 따라서 더 큰 타입을 사용하거나 오버플로를 확인


### &&와 ||의 단락 평가란 무엇인가요? 조건식의 순서가 중요한 예를 들어주세요.
- 단락 평가란 앞의 조건으로 결과가 결정되었다면 뒤의 조건을 평가하지 않는 것
- A && B 에서는 A가 false이면 전체 결과가 이미 false이기 때문에 B를 평가하지 않음
- A || B 에서는 A가 true이면 전체 결과가 이미 true이기 때문에 B를 검사하지 않음
- 조건식의 순서가 중요한 예, name이 null이면 조건식의 앞의 결과가 false이기 때문에 조건식의 뒤를 검사하지 않음, 따라서 NullPointerException이 발생하지 않음
```Java
String name = null;
if (name != null && name.length() > 0) {
  System.out.println(name);
}
```

### String이 불변이라는 것은 무슨 뜻인가요? 문자열 변수에 다른 문자열을 대입하는 것과 모순되지 않나요?

### 객체지향 프로그래밍이란 무엇이며, 대표적인 특징은 무엇인가요?
- 객체지향 프로그래밍은 데이터와 동작을 객체 단위로 묶고 객체들이 서로 협력하도록 프로그램을 설계하는 방식
- 캡슐화, 상속, 다형성 등의 특징이 있음
- 유지보수성, 테스트 용이, 확장성을 높일 수 있음

### 캡슐화란 무엇이며, 왜 필요한가요?
- 객체의 내부 상태와 구현을 외부에서 직접 접근하지 못하게 하고, 정해진 방식을 통해서만 상태를 다루도록 만드는 것
- 잘못된 상태 변경을 방지하고, 내부 구현이 바뀌어도 외부 코드에 미치는 영향을 줄일 수 있음

### 오버로딩과 오버라이딩의 차이는 무엇인가요?
- 오버로딩은 같은 이름의 메서드를 매개변수를 다르게 하여 여러 개 정의하는 것
- 오버라이딩은 상위 타입에서 정의한 메서드를 하위 타입에서 재정의하는 것, 메서드 시그니처가 동일

### 다형성이란 무엇이며, Java에서는 어떻게 활용하나요?
- 다형성은 사용하는 방법은 동일하지만 실제 동작과 결과가 다양하게 나오는 성질
- 어떤 인터페이스를 구현하는 여러 클래스를 만들 수 있고, 하나의 인터페이스 타입 변수로 하위 객체들을 받아 오버라이딩된 메서드를 호출하면 실제 객체의 구현이 실행됨, 따라서 호출 코드가 구체적인 구현에 덜 의존하게 만들 수 있음

### static 멤버와 인스턴스 멤버의 차이는 무엇인가요?
- static 멤버는 클래스 자체에 속하고, 인스턴스 멤버는 각 객체에 속함
- static 멤버는 클래스에 하나 존재하여 모든 인스턴스가 공유, 객체와 무관하게 공통으로 사용하는 값이나 기능을 정의할 때
- 인스턴스 멤버는 각 객체마다 별도로 존재

### Java의 인자 전달 방식은 Call by Value인가요, Call by Reference인가요?
- Java는 항상 Call by Value(값에 의한 전달)임
- 기본 타입은 값 자체가 복사되고, 참조 타입은 참조값이 복사됨
- 인자로 참조 타입을 전달하면 메서드 내부에서 매개변수의 참조가 바뀐다고 해도 호출자의 참조는 변하지 않음

### final을 변수·메서드·클래스에 붙이면 각각 어떤 의미인가요?
- 변수에 final을 붙이면 한 번 값을 대입하면 값을 변경할 수 없음(다시 대입 불가)
- 메서드에 final을 붙이면 해당 메서드를 오버라이딩할 수 없음
- 클래스에 final을 붙이면 해당 클래스를 상속할 수 없음

### 상속과 합성의 차이는 무엇이며, 어떤 기준으로 선택하나요?
- 상속은 is-a 관계, 한 쪽이 다른 한 쪽의 한 종류임을 나타내며 주로 상속이나 인터페이스 구현으로 표현함
- 합성은 has-a 관계, 한 객체가 다른 객체를 구성 요소나 기능으로 사용하는 관계
- 단순한 기능 재사용이나 여러 기능을 조합하려는 목적이라면 합성을 고려하고, 명확한 타입 관계와 다형성이 필요할 때 상속을 고려함
